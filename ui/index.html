Credentials

What is stored here, exactly

  • What: this machine's own sudo password. Nothing else. No other machine's password is ever stored here, and this one is never sent anywhere.
  • Where: ~/.config/sukarfleet/secrets/sudo.cred, mode 0600 inside a 0700 directory, sealed by systemd-creds so the file is bound to this user on this host.
  • It protects against: a copy of the file turning up somewhere else — a synced repo, a backup, a directory copied to another machine. The sealed file is inert anywhere but here.
  • It does not protect against: a process already running as this user on this machine — it can unseal the file exactly the way the daemon does. Nor does it protect a stolen disk: this machine has no full-disk encryption, so an attacker holding the disk holds the sealing key too. Storing a sudo password here is equivalent to granting root on this machine to anything that can run as this user, including the agent.
  • Also true: SSH-as-this-user plus this stored password is root on this box. The forced command= in authorized_keys narrows a paired peer to one verb; it does not remove that fact.

Admin lane

Two independent switches. The first decides what this machine may send; the second decides what it will run for others. They are separate on purpose: a machine can serve the lane without being able to drive it, or the reverse.

Off means no privileged command can be started from this console at all, including one aimed at this machine itself.

Off means an admin command sent to this machine is refused before it reaches sudo, whatever it is paired with.
